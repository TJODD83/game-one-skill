# Shape creation and UV guide

## Image-led modelling rule

Build with the workshop’s editable silhouette and supported operations on actual selected surfaces. Do not replace a requested hole, mound or other detail with a placed primitive. Inspect the source, record face-local placement and evidence, apply supported operations, and validate and save actual geometry. If the required tool is not implemented, report it as blocked. Independent moving components require explicit evidence and linked assembly data. The full observation, decision, cost and validation sequence is in `AI_PRIMITIVE_GUIDE.md`.


This guide applies to every built-in shape and to the experimental outline panel. It is a set of checks and capability records, not a claim that every operation is implemented on every shape.

## 1. Shape and source

Record the shape type, editable dimensions, source reference, view and assumptions. An image-guided outline is an observation, not a measured 3D reconstruction. Missing or hidden surfaces remain estimates.

## 2. Contour and topology

Track the outline points and the actual connected mesh separately. For the outline panel, the curve rule measures turn angle and convex or concave direction, a chosen curve size, and per-point sharp or round overrides. It does not detect a curve in the reference image. The panel has front and back contours and an extruded perimeter wall. The side-wall quads are available to the shared edge and face-loop inspector. New profiles use the current inset-band experiment; deliberately selected older cap settings remain object overrides.

Other primitives use their own declared loop, face and rounding support. See the shape catalogue. A successful 2D contour does not prove quad edge flow, support loops or modifier compatibility.

## 3. Features and layers

Record each hole, mound, crease, round, repeated pattern or mirror as a separate operation with its input target, dimensions and supported shape. Only run operations that are implemented for that shape and surface. Changing geometry invalidates earlier UV and AO evidence. The outline panel supports whole-perimeter rounding, but not holes, mounds, creases or arbitrary independent 3D edge-loop modifications.

## 4. UV geometry

Generate UVs from the actual current mesh and atlas settings. The geometry checks cover overlaps, bounds, degenerate triangles and stretch. A geometry pass is not an orientation pass. The cylinder side has a documented intentional 50% compression, which needs separate review.

## 5. Six-view UV direction

Use the top, bottom, front, back, left and right direction inspector on the current model. Its world axes and bottom-view convention are provisional and can be adjusted as expected directions. It reports triangle-level matches and differences using dominant normals. It does not rotate or repair UV islands and does not establish their semantic meaning. Curved, sloped, occluded, mirrored and multi-part cases require review. Verify object/world-space placement separately from face text direction.

## 6. Shading, AO and delivery

Review normals, seams and thin triangles; numeric checks are not the same as visual or engine proof. Generate a fresh AO map after geometry or UV changes. AO stays separate from flat albedo. Save the editable source settings, references and actual validation results. Treat unrun checks as unverified, never as passing.

## Amazing box out: layered silhouette foundation

The aim is an editable, image-informed foundation for a more detailed asset. A person or agent first places an ordered closed outline against a reference view; a perspective photograph does not give measured front, back, top or depth dimensions. The outline is an observation, and unseen surfaces and depth are explicit assumptions. The geometry rules do not perform image edge detection or infer plastic or other material properties.

1. **Outline corners:** New profiles default to automatic corners; an explicitly saved sharp setting is retained. The automatic rule measures the turn from one segment to the next and classifies the point as convex, concave or straight. A minimum angle, corner-type filter, maximum fraction of the shorter adjacent segment and per-point overrides are editable. With angle scaling enabled, the fraction is multiplied by `min(turn / 90°, 1)`: a 45° turn receives half the chosen maximum and a 90° or larger turn receives the maximum. This is a chosen geometric rule, not a measurement of the reference. When older saved settings omit this option, loading applies the current angle-scaled default. This can change automatic curves; an explicitly saved on/off choice is preserved. Review the regenerated silhouette and UVs.
2. **Depth and end edges:** One extrusion produces both end caps. The separate end-edge rounding percentage applies equally to both ends; its distance is that percentage of the smallest of the outline's width, height and extrusion depth, in the object's local geometry coordinates. The cap is inset by that distance and sampled near-cap rings create a rounded transition to the wall. The long wall has no unnecessary centre ring. Scaling the object afterwards changes the dimensions in world space, including potentially making the rounding nonuniform. The optional mirror control creates another object; it is not needed to make the opposite cap.
3. **Current boundary:** Whole-perimeter rounding accepts convex and concave simple outlines when the inset is safe. New profiles request the same 6% default as the box. If a narrow feature would collapse, the fitted inset deterministically reduces the actual amount; the UI reports both the requested and applied values. For the default arcade profile, 6% requests 3% actual; the common round handle and the shape settings report the limited value. The default UV uses separate per-edge strips to reduce stretch, which adds seams. The silhouette UV setting can experimentally attach the rounded bands to each face while retaining the outer profile in the UV. It warps the flat cap and does not alter the 3D geometry. This candidate fails the stretch check on the default arcade (about 3.19× versus the 1.25× limit), so it is blocked for export and painting until improved. The six-view orientation is still unverified. The local default arcade audit also reports thin triangles and gentle normal breaks; inspect shading and topology visually before delivery. Geometry changes still require UV direction and shading review. Older projects missing this setting keep 0%.
4. **Cap topology:** Silhouettes load with the current quad generator: offset perimeter bands, a sparse quad core and automatic horizontal and vertical cuts when a safe connected route is found. It may add boundary samples without moving the authored outline. The cuts can bend and poles can interrupt selection; this does not prove an artist-quality grid. If a quad core cannot be constructed, generation reports an error and never substitutes editable triangular faces. If only a requested cut cannot be routed safely, the valid uncut quad geometry is retained with a warning. Earlier row-based caps are available as an explicit archived choice and likewise report failure when unsupported. The graphics renderer draws each editable quad as two triangles.
5. **Later features:** Holes and mounds should eventually support face-relative size, placement across valid connected bands, inward/outward profiles, bounds, repetition and optional mirroring; these operations do not yet work on the outline panel. Their constraints must be checked against the actual topology, and geometry changes require fresh UV, orientation and shading checks.

The six-view inspector remains a diagnostic: it does not rotate or fix UV islands, establish semantic face orientation, or prove an asset ready to paint. Saved data and generated geometry must be checked together; do not claim a live account save or visual verification without observing it.

## Arcade outline example in the workshop

The workshop offers **Arcade · rounded silhouette** and **Arcade · original**. Both use the same approximate side control points; the rounded example enables the angle-scaled outline rule. They do not represent two different image analyses. The example is made of independent scene objects. Both side panels have the same link identifier within their assembly; the selected panel's link checkbox applies a validated edit to both without sharing a mesh instance. Clear the checkbox to edit only one.

Select a side panel to use the workshop's outline point editor, per-point curve overrides, and curve/depth controls. Its current profile parameters and link identifier travel with the saved scene. New outline, round, hole, and cut actions are logged per object as bounded tool history. The current shape fields remain the geometry source; this history is not a complete modifier stack or a universal replay/undo system. Older saved models are not silently rewritten and do not acquire an invented history. Reopen an older arcade to inspect its own settings, or use the new example for the rounded starting point. Existing unsupported operations, UV and concavity limitations above still apply.


## Shared shape baseline and older objects

Every supported object carries a baseline version and its shape kind. The shape catalogue defines its generator defaults, topology and operations that actually exist. Object transforms, supported feature settings and shape-specific data remain with the individual object; a silhouette stores its control points, depth, curve rule and end-edge amount. A box remains a box with the existing box topology. These are deterministic inputs, not LLM guesses.

When a model or outline project is opened, missing baseline fields are filled using current rules. Missing silhouette angle scaling becomes enabled, and a missing end-edge amount becomes 0%. Explicitly saved settings are preserved. Because angle scaling changes the width of some automatic corners, opening a legacy automatic outline can produce different geometry and requires new UV and AO checks. The server returns the migrated view without rewriting the old database record; a later save stores the migrated settings. Older local scenes are similarly normalized when opened. Unsupported versions or invalid regenerated shapes are rejected rather than silently destroying the saved record. Historical actions are not rewritten.

The common baseline does not make holes, mounds, creases, selectable loops or UV orientation correction available on every shape. Shape-specific support remains listed in the catalogue and the UI. The saved action list is not a complete replayable feature stack.

## Profile-only boxout and decision workflow

The workshop's **Arcade profile · boxout** example opens one selected profile, with no cabinet components or controls. Its starting depth is 0.45 local units, and the shape is an approximation based on the earlier arcade profile, not a new image trace. It can be saved as an ordinary editable scene.

The controls next to the 3D view use the same profile parameters and geometry generator as other outline objects:

- **Corner curve size, 0–40%:** maximum trim as a fraction of the shorter neighbouring edge. Zero produces sharp corners that follow the global rule. Angle scaling and any per-point choices still apply.
- **Minimum corner turn, 5–150°:** the change in direction required for a point to be rounded automatically. A larger threshold generally affects fewer corners; this is not the interior angle. Changing either corner slider enables the automatic curve rule.
- **Extrusion depth, 0.01–5 local units:** the distance between the two caps. This does not add an object or a centre loop. Object scaling can change the resulting world-space depth.

Moving a slider regenerates the profile, invalidates prior UV/AO evidence and records the final adjustment in object history. The UV geometry and six-view direction checks remain separate; profile painting and AO remain blocked until orientation is verified. Profile holes, mounds and arbitrary independent 3D edge rounding are still not implemented; the quad cap is experimental.

For a future image-led decision API, keep these stages separate: (1) record the image, chosen view and whether it is perspective; (2) capture observed outline points and uncertainty, distinguishing estimates from measured data; (3) apply and expose the deterministic corner and depth rules; (4) propose holes or mounds only where supported targets and dimensions exist; and (5) regenerate geometry and rerun topology, UV, orientation and shading checks. Preserve action reasons, actual tool calls and provider-reported usage where available. Never invent token counts or call an LLM observation an edge-detection result. The current MCP service supports project inspection, point edits and configuring existing shape settings; it does not autonomously examine a new image, infer features or create unsupported holes and mounds.

## Individual outline node decisions in the workshop

The global curve-size and minimum-turn sliders provide the starting rule for the whole silhouette. In the 3D workshop, select a profile and choose **Outline nodes** to see its control points as numbered guides. These guides represent the original control points; a rounded corner may not contain an actual mesh vertex at the guide position. Select one guide and use the on-object **Node curve** and **In/out** drag handles. **Use rule** clears both local values. Depth, global curve size and minimum turn also have on-model drag handles, with keyboard arrow support. The outside controls remain available. A selected profile uses the shared wireframe inspector. **Edge loop** and **Face select** use the actual mesh topology: the side wall can form a closed face band around the silhouette, while quad-cap faces can also be inspected as bands; transition patches and poles can interrupt predictable flow. Unsupported quad paths are reported instead of creating triangular caps. Holes, mounds and arbitrary independent 3D edge rounding on profiles are still unavailable. Whole-perimeter rounding uses the common **Make round** and **Round** handles.

Each node may store its own 0–40% fraction of the shorter neighbouring edge and an inward/outward bias from −100% to +100%. The bias changes the curve relative to its neutral shape, with tangents along the neighbouring edges; it does not convert a convex corner to a concave corner or vice versa. Bias has no visible effect while a node is sharp. A numeric local value overrides the global curve amount and automatic threshold for that node; zero keeps it sharp. A node set to the global rule continues to follow the global sliders and angle scaling. The `sharp` override has precedence until a numeric node value is set. Changing a node preserves the other nodes and global controls; linked panels are updated together only when their existing link option is enabled. Node values, geometry settings and accepted actions are saved with their object or outline project. Invalid or crossing curves are rejected.

The separate MCP tool `set_outline_node_curvature` accepts the project, current `updated_at`, zero-based `node_index`, a `radius` fraction and/or `bias` value (null clears that local setting), and a reason. It validates the resulting outline and records the accepted action. It rejects stale revisions and out-of-range node values. Inspect the project again after points have been inserted or removed: stable node IDs are not implemented. An agent may decide a node's value using the evidence it actually has, but this service does not itself detect a silhouette or interpret an image. A future shape-detection algorithm may suggest nodes and curvature; those suggestions remain reviewable decisions. Record actual evidence/tool calls and use unknown for unavailable token counts.

Geometry changes invalidate earlier UV and AO results. Use the existing topology, UV geometry, six-view orientation and shading checks. UV orientation is still a diagnostic, not an automatic repair, and profile painting/AO remain blocked pending orientation verification.

## Backend topology proposals

The MCP tool `analyze_outline_topology` examines the unrounded control polygon in the supplied world transform, identifies unusually long edges relative to the median, and proposes additional boundary points and nearest visible horizontal or vertical connections. It is a read-only backend analysis, with no popup or guide overlay in the 3D viewport. Proposed points and lines are not mesh vertices or selectable loops. The separate experimental row-cap and transition-grid meshers generate real geometry; they do not use these analysis proposals.

## Alternative curved-corner marching order: proposed, not implemented

1. Validate the closed silhouette and its 2D corner curves. Sample each curved corner at approximately 20% from each end, by curve length, while preserving endpoints and tangents. Retain these as boundary candidates, not automatic interior triangles.
2. Derive a safe interior support position for each sampled point using local feature clearance. Start near 20% of the available local inward distance, not 20% of the entire object; reduce or reject the value when a narrow feature or concavity would cause a crossing. Two support paths per curved corner are a proposed starting layout, not a guarantee of two uninterrupted loops.
3. Split unusually long boundary sections at valid projected node alignments, then trace horizontal and vertical visible paths through the silhouette. Split crossings into shared vertices and stop or route paths at concavities; do not connect through the exterior.
4. Build conforming quad patches from the boundary and support paths. Resolve differing edge counts and unavoidable poles explicitly, preserving the user-visible outline. For cases that cannot be safely quadrangulated with these rules, report the unsupported region rather than presenting candidate lines as quads.
5. Connect the cap topology to the existing perimeter rounding rings and the opposite cap without an unnecessary centre loop. Render quads as triangles if required by the graphics engine, but keep their logical quad identities for selection.
6. Validate closed geometry, crossings, face adjacency, loop continuity, normals, thin triangles, UV geometry, six-view orientation and visual appearance. Record the result and do not bypass UV or AO gates. Profile holes and mounds remain later operations.

## Face-attached silhouette UV experiment

The selected profile's **Silhouette UV** control chooses the default separate corner strips or the experimental **Corners on face** layout. On the latter, the cap is mapped into an inset and the rounded bands occupy the area up to the original rounded outside contour, so the actual UV islands show that outline. The 3D position and topology are unchanged by this UV choice. The cap inset is a mean-value coordinate warp; if it cannot fit, the operation is rejected. UV overlap, bounds, degeneracy and stretch checks still apply; the alternative is not paint-ready simply because it has a recognizable outline. The agent's `configure_outline_shape` accepts `cap_uv` as `strips` or `silhouette`, and saved settings persist with the profile.

## Live profile defaults and the box UV comparison

On load, legacy profile objects and outline projects inherit the current corner rule, end rounding and quad-cap settings only where those values were missing. A `defaultBindings` list records which of those properties continue to follow the current tool defaults on later loads. Explicitly stored shape dimensions and corner values, including zero rounding, remain overrides. Previously disabled or unversioned quad caps migrate to the current generator; an explicitly archived cap remains an override. Changing a bound property in the workshop or through the agent makes it an object override; **Use shape defaults** restores the bindings, including resetting individual node curve overrides. Points, depth and transforms remain object data. If the quad generator cannot fit a profile, loading reports an error and leaves the existing scene and saved record unchanged. Opening a model does not write it back to the database. Regeneration and default resolution happen on load and on a workshop edit; already-open scenes are not subscribed to a live catalogue stream.

The box has two different rounding UV paths. Whole-face rounding uses separate curved strips; the selected-edge box method retains face islands, splits by source face, then iteratively relaxes vertices against 3D edge lengths. A local unit-box corner example passed at about 1.11× stretch. On the arcade's face-attached silhouette UV, the current mapping measured about 3.19×. An exploratory application of the box-style distance relaxation with the original silhouette boundary fixed produced overlaps and worse distortion; an unpinned version also overlapped and did not preserve the requested boundary. Neither test was integrated. Do not claim the silhouette UV passes, or generalize the box result to this outline. Improving it needs an outline-preserving, non-folding solver and the existing UV, orientation and shading checks.

## Experimental planar face inset bands

`plan_face_inset_bands` accepts an ordered simple 2D face boundary in face-local coordinates (do not repeat the first point), a requested fraction of the shorter original bounds, a band count, collapse tolerance, turn-angle limit and optional protected input-node indices. It produces actual 2D quad faces grouped by band and nested boundary rings. Each inset uses a constant-distance offset, not a scale around the centre. The safe-fit routine may reduce a requested distance for tight corners; return the requested and applied values. Node reduction removes pairs only when the two inner samples meet the local turn and chord-deviation limits, are not protected, and the transition is made of convex quads. Closed boundaries, face area, edge incidence and face overlap are checked; an unsafe reduction falls back to retaining points. Output tracks each surviving node's input index. These are per-run indices, not persistent cross-edit IDs.

The outline agent's `inspect_outline_project` also returns `sampledOutline` and `sampledSourceRefs`, mapping the rounded samples back to their control node and sample positions. A caller can pass the indices for sharp nodes and the first and last sample of each curve as protected indices. For the current arcade example this protected three-band test produced ring counts 51 → 43 → 43 → 41; requested 0.102 units per band was limited to 0.01275, 0.01275 and 0.0031875 units. These are calculated local units for that example, not measurements of the photo.

This is a reusable planar-boundary backend experiment, not yet a general 3D face operator. It does not yet resolve face-local coordinates for arbitrary selected meshes, create or save 3D geometry, stitch its inner boundary into the cap quad grid, expose selectable bands in the workshop, or make holes or mounds. Its indices and patches must not be represented as 3D mesh loops. The generic planner is 2D; the silhouette adapter described below uses it to construct actual 3D cap bands.

The existing Shape Testbed has a bounded 3D example under **Box → Inset face bands**. It applies one to four generated quad bands to a chosen uncut box face, keeps each band tagged separately, and checks the closed mesh and UVs. A 2D arcade contour view uses the same planar planner and protects curve endpoints. Its reported rings are a diagnostic only: they are not stitched into the 3D arcade. The named-band selection function is tested in code; the silhouette editor supports face-loop inspection, while holes and mounds on these bands are not yet implemented.

### Silhouette face bands in the workshop

Select an outline panel. The current inset bands are enabled by default; adjust Total band depth and band count. Width and band count are saved as the silhouette shape cap setting and regenerated on load; edits are recorded in the existing shape history. The shared boundary planner builds quad bands on both profile caps, stitched to the perimeter and extruded sides. For supported outlines, the inner face can be filled with a sparse quad patch. Requested horizontal and vertical cuts follow opposite sides of connected quads across the cap, inset bands, rounded rim and extrusion. These cuts use local silhouette axes and may bend; they are not exact straight world-space cuts. Face selection cycles through horizontal, vertical and, for an inset face, perimeter selection. Width can be reduced by the safe-fit calculation; check the status and UV audit before use. The same operation can be tested on an uncut box face in the Shape Testbed.

New outline panels start with a neutral four-point boundary. The arcade is an optional example supplying its own points; the generator and face-band operation do not require an arcade object or image.

## Current generator and earlier experiments

The workshop uses one silhouette generator. Its current face experiment is **symmetric inset bands**, with three bands requesting 15% total depth by default (5% per band). Total band depth is a fraction of the shorter original face bound; actual distance can be reduced where a safe inset cannot fit. The slider changes the total requested distance and the band count divides it into equal requested steps. Each completed band remains a named connected 3D cap band.

Curve points are associated with their source node. The current experiment tries removing the matching inner samples (1 and 3 of the five-point curve) together while preserving the endpoints and centre. It accepts the transition only if the geometric and overlap checks pass. If it cannot safely remove both, it retains them and can try again at the next band. A later band can collapse the remaining three samples to one point where validation succeeds. A sparse quad core and connected axis-guided cuts are generated for supported shapes; unsupported cores report a construction error rather than becoming triangular faces. Holes and mounds are not yet implemented.

New shapes and records bound to the cap default regenerate using the current experiment. Explicitly archived cap choices, current inset parameters, outline nodes, depth and transforms remain object data; opening a scene does not rewrite it. **Earlier face versions** permits an object to select the previous inset reduction or the earlier quad grid. These are actual alternative algorithms in the same generator, not separate scene generators. The normal view shows the current version and hides these options until expanded. Source and deployed site versions provide the historical record of whole application releases; choosing an earlier face algorithm is not a rollback of the complete application. No in-workshop global release rollback is implemented. UV, shading and six-view checks remain required after any version or topology change.

The **Open silhouette boxout** link uses a separate browser-local workspace with one editable silhouette and current generator settings. It preserves the regular scene. Its band colours correspond to actual cap triangles and are a temporary inspection overlay, not texture or UV changes.

### Silhouette face and depth loops

The current shape defaults request one horizontal and one vertical loop; their counts are editable in the silhouette settings and are saved with its parameters. Quad strips are split through opposite edges, interpolating position, UVs and normals and retaining the perimeter-band metadata. The proposed strip must be closed, cross both an inset band and the depth, and pass an axis-alignment test in the silhouette plane. A route can turn; this is not an exact straight world-space cut. Unsupported outlines or failed routes are reported and the uncut geometry is retained. For the boxout fixture, independent checks found no open/non-manifold edges, inverted normals, degenerate triangles or overlapping UVs. The GPU still draws each editable quad as two triangles. Six-view UV orientation and actual device interaction remain separate checks.


## Silhouette depth guides and directional surface selection

The profile generator adds two closed quad edge rings at 5% of local extrusion depth from each cap. The Depth guide slider can change the distance from 1% to 20%; it is saved in the profile's cap settings and regenerates with the shape. These are actual selectable topology, not overlay lines. No ring is added at the centre.

The generator records each cap axis and ordered silhouette perimeter segment, including rounded strips. Where the extrusion faces world left/right, the highest and lowest contour segments mark top and bottom, and the two paths between them become front and back based on world Z. The entire front path stays front through slopes and controller ledges. If the object is turned so its cap faces world front/back, or the front/back paths are ambiguous, the current implementation falls back to dominant world-axis classification; this is provisional for arbitrary outlines. Colours are on by default and selection and wireframe remain visible. The regions colour the actual triangles and their current UV locations. Select surface highlights all faces of that direction in both views. Choose Inset bands to see the individual cap bands; in Face select mode, tapping one selects that full band and tapping again cycles horizontal and vertical quad bands. Quad traversals can stop at poles. Profile holes and mounds are not implemented.

The displayed region colours are masks over the **existing** UV mapping. They do not yet mean that front, top and bottom have a connected unfolded directional net, or that left and right lettering directions are approved. A connected-strip candidate showed no overlaps on the tested arcade outline but about 2.06x maximum stretch and failed the existing six-view direction check; it is not the active layout. Keep orientation, stretch, paint and bake gates in force until a replacement net is verified on the actual mesh. World-space surface groups are recalculated after object transformations; UV orientation still requires a separate review.


## Quad-cut limitation and measured drift

The current connected horizontal and vertical loops split the chosen existing quad strip at each quad edge midpoint. They do not start at inset-band points and are not guaranteed straight in silhouette coordinates. Each cut reports the range of its cap coordinates as `capAxisDrift` and records `placement: quad-midpoints`; the workshop displays the measured drift. For the default boxout the generated horizontal and vertical cuts drift roughly 0.20 and 0.22 local units respectively. A route analysis found that the present sparse fan-like core supports only a small number of strictly axis-aligned through-routes; making all requested margin-point paths requires rebuilding the quad patch and its transitions, rather than drawing lines or hiding triangles. No inset-anchored quad reconstruction or new directional UV net is claimed yet.


## Current ordered front and corner audit

The current silhouette requests a 5% inset step (relative to the shortest face bound), with three rings by default. The safe-fit calculation may apply a smaller distance. The Corner reduction details and `inspect_outline_project.actualFaceTopology.cornerMarch` report how many curve samples from each source node survive in every real ring. Sharp nodes and incomplete transitions are identified. This accounting is generic over the supplied source nodes; the existing actual reduction algorithm still assumes a five-sample curved node and a maximum of four bands, and does not guarantee every rounded corner reaches one point. Existing user overrides remain overrides. Rebuilds and checks report failures rather than using editable triangle caps.

This release does not create the requested inset-point horizontal/vertical topology or the new front-arc UV strip, hinged or separated top/bottom charts, and longest-back-edge attachment. Surface grouping alone does not constitute a UV unwrap. The existing UVs and their separate six-view orientation and stretch gates remain in force.


## Unboxed silhouette UV net (experimental)

Silhouettes with no saved UV choice use **Unboxed net** by default when the contour has a suitable back edge. An explicitly saved UV choice remains an override. Unsupported contours retain the separate strips and report a warning. It builds UV coordinates on the actual connected quad geometry: the front wall is a continuous measured strip between the two profile caps; top and bottom share UV boundary vertices with the front; the back is joined to the left side along its longest vertical straight run, or a sloped straight run if there is no vertical one (a deterministic choice when both extruded sides have equal length). Front/back order comes from the outline path, not from reclassifying each slope. Adjacent collinear edges are kept in one back run. UV splits, bands and caps follow the existing generator and atlas packer. The net is saved as `capUv: unboxed`; unsupported contours with no suitable back edge return an error rather than claiming the join. Other UV modes remain available.

On an unrounded rectangle, a local test passes zero overlap, zero degeneracy, approximately 1.00× stretch, and all six orientation checks using a 180-degree top/bottom expectation for the front-hinged convention. On the rounded arcade fixture the actual geometry has zero overlaps and zero degenerate UV triangles, but approximately 1.50× stretch against the 1.25× gate; the default top/bottom six-view convention also differs and the bevel directions need review. Export and paint remain blocked. The layout is built in silhouette-local coordinates, and a rotated or mirrored object has not been proven to regenerate the requested world-facing layout. The tool does not yet support every outline or the inset-point horizontal/vertical quad reconstruction. Do not present this candidate as production-ready.

### Silhouette region curves
The silhouette classifier grows the highest and lowest boundary segments across connected segments whose outward direction is within 45 degrees of world up or down. The front and back remain continuous paths between these runs. The unboxed UV generator unfolds the entire top and bottom runs from their front hinges, using the existing stretch gate. Classification uses world transforms when selecting and colouring surfaces; the generated net is silhouette-local and does not yet regenerate world-oriented UVs on rotation. A shape with an ambiguous or overlapping partition remains unsupported rather than silently losing a region.

## Ring profile experiment in the Shape Testbed

`Box → Ring profile · mound / hole` builds a single connected mesh on one uncut box face. The experimental radial profile defaults to 24 segments and a neutral in/out curve; ring mode, curve, segment count, height and inner radius can be changed. The centre can be flat, close to a single point, or contain a centred circular, elliptical, square or cross blind recess. The centre outline uses the existing feature-outline parameters; a fit check rejects outlines that cannot fit. The host box face, ring bands and hole floor share connected planar UV coordinates; the depth wall is a separate strip. Geometry, UV stretch and shading must be audited each time.

A profile turn of at least 35 degrees is reported as a possible part boundary. Sharp turns alone do not establish mechanical separation; the test does not split objects, create a movable button, save a ring shape, support free profile nodes, place features on a silhouette, or implement path sweeps, mirror/row patterns or a general modifier stack. Do not describe this prototype as a completed workshop ring tool. The new connected layout fails the local 1.25x UV stretch gate (approximately 1.28x for the default sloped ring); earlier passing results referred to a different, strip-based layout. No production approval is claimed.

### Ring outlines and profile experiments

The box-face ring test can choose a circular, elliptical or sharp square perimeter; a slope, sharp ridge or sampled rounded ridge; in/out curve; crest position; mound/recess; radial segment count; inner radius and height. Square segments must be divisible by four. The rounded profile is sampled geometry and its face normals still need shading review. This remains one testbed mesh, not an independently movable button or an editor modifier. The pre-existing selectable profile silhouette is not yet an arbitrary hole or mound outline on another silhouette.

### Proposed image-led detail stage

1. The agent observes a supplied reference and records the proposed host, visible feature outline, estimated position and uncertainty; perspective appearance is not a measurement and geometry is not automatically detected by these tools.
2. Select an actual face or connected region on the current model. Define a local surface frame and convert the proposal into a bounded centre, size and rotation. Flag occluded or unsupported surfaces instead of claiming an observation.
3. Choose an existing supported outline and mound/recess; choose profile defaults and any reviewed overrides. Repeat/mirror must respect the host's topology and fit, with collision and boundary checks before changes are committed.
4. For a mechanically independent button or bezel, require an explicit component decision and parent/attachment relationship. A sharp turn can suggest a boundary but does not prove one; current ring tests do not split objects.
5. Regenerate affected mesh and UVs, audit topology, overlap, stretch, face ownership and six-view direction, invalidate old UV/AO/paint and preserve per-object settings/history. Front/back, top/bottom and side conventions still need actual-model review; image interpretation, arbitrary selected-face edits and parametric assembly attachment remain unimplemented.

Examples of future silhouette detail: recessed rectangular screen on the front, shallow ellipse ridge around a control on the top panel, or an irregular inset made from a saved outline. They require actual surface-local cuts, stitching and suitable UV charts; the current prototype provides no such silhouette operation.

### Capsule experiment

### Hole-floor band and connected UV experiment

The ring-on-box testbed builds the floor of a circular, elliptical, square or cross blind recess with three real quad bands. ### Experimental placement and width-profile tools

`plan_face_feature_placement` is a read-only agent operation for a rectangle inside one caller-supplied 2D face boundary. It calculates boundary margin, rotated footprints and an optional reflected pair with a clearance. This is a geometry plan, not an inspection of a real selected host, a mesh edit or an image interpretation; curved and multi-face targets are not supported. Keep host identity, surface mapping and image accuracy unverified.

The source module `profile-width-profile.mjs` contains an experimental width/taper deformation of an actual profile mesh along its local length. It preserves the side projection, copies the original UV coordinates and reports them as unverified. Existing vertex slices limit the resulting shape. The read-only agent command `evaluate_outline_width_profile` can temporarily evaluate this on an owned saved outline without changing or saving the model. It is not connected to saved scenes, agent jobs or the workshop UI, and it does not implement per-node cross-depth shaping or top-image tracing.

The job silhouette gate now checks whether the requested horizontal and vertical cuts actually exist in generated geometry. Missing cuts block the stage; its result also reports band and corner-march metadata. These checks do not establish exact alignment, UV quality or image fidelity.

The depth gate regenerates and checks the requested-depth mesh before changing the saved outline and checks it again afterward. Historical jobs already past depth are checked against their current saved outline when opened; a failed or stale result is shown as invalid rather than accepted. This does not repair the mesh, validate UVs or undo an old depth change.

### Node-anchored edge-loop closure audit

Each current inset generator records the innermost available point for each authored outline node and its corner-convergence status. The optional `audit_outline_node_axis_loops` operation inspects actual selectable geometry at those points. The workshop’s **Check selected node routes** instead reports the chosen route and actual depth station without requiring both straight directions. Horizontal is local Z, vertical local Y and extrusion depth local X. For each direction it requires an axis-aligned edge at the node on the positive cap, a closed walk using the workshop's valence-four edge-loop selector, and a path through both caps. It reports missing anchors, missing edges and pole-stopped or off-axis paths. This is read-only, does not build a path, and does not check UVs or resolve incomplete 5/10/10 convergence. The strict check is available through `audit_outline_node_axis_loops` as a diagnostic, not a job requirement; an angular route must not be judged by an unrelated straight-axis count.

A local experimental axis-grid construction demonstrated why simple axis slicing cannot be accepted as the requested node system: on the nine-node arcade fixture it produced 13,448 triangles from 1,356 and generated a geometric closed cycle whose real edge-loop selector stopped at a pole for at least one route. The prototype is not installed as a shape tool. A proper generator must preserve node-to-band lineage, make horizontal and vertical routes through the caps and depth walls, resolve valence at path intersections and corner convergence, then check the actual loop selector, manifoldness, triangle quality, UV continuity and polygon budget. Surface-closed paths or quad count alone are not proof.


The corner reduction now tests each valid concave transition using a safe diagonal, and tries non-conflicting reductions independently. When a local transition cannot fit it can adjust the inner centre by a bounded factor; applied local adjustments are reported. This improves the saved ten-node arcade test from 2/8 to 8/8 rounded corners converged in its regenerated geometry. Sharp corners stay sharp. This fixture has 1,440 render triangles, no reported non-manifold edges or inverted normals; its unboxed UV remains blocked at 1.683× stretch. This is not proof for every contour. It still reports 0/20 closed node-axis routes; the existing midpoint loops do not implement the requested node-based loops. The current inset configuration is three nominal 5% bands and individual applied widths may be reduced to fit; it does not independently implement a distinct 5%, 10%, 10% band sequence.


## Saved per-node opposing stations

The selected profile's **Selected node route** controls save explicit per-node original/off, horizontal, vertical, both, and angular choices with the scene. The angular target is derived from the first boundary across the selected local horizontal/vertical axis and a perpendicular projection to that segment within the angle limits. The actual profile generator inserts matching boundary stations and checks that each has a selectable depth path. Single matches are supported; the existing generator may add a separate split to maintain safe quad parity. The selected-node status reports zero if no valid station is found. New profiles default to horizontal for unspecified nodes; older saved profiles retain their prior default. Off, horizontal, vertical, angular and horizontal-plus-angular can be selected per node, or applied to all nodes. If the default cannot generate safe geometry, the original mesh is kept and a warning is shown.

This does not guarantee a straight selectable route across the caps, angle-directed corner bands, world/view-axis mapping, multi-face features or approved UVs. The original outline-project agent tool remains read-only for these settings; the saved scene path and model library are separate. Rebuild UV and AO after editing.


## Ordered authored-node surface groups

The selected profile can select a real across-depth sidewall span using two authored node indices and save a named group. The forward node order wraps at the end; shared boundary-corner faces may belong to neighbouring spans. Routing, rounding and parity support points are included in the surface and ignored as authored selection targets. The group stores node indices and is rebuilt with the profile. The agent can inspect and record supplied named groups with view, intent and evidence on an owned outline; it does not detect the image, modify an existing scene or execute a feature. Arbitrary cap patches, holes/mounds and per-node cross-depth curves remain unsupported.
